# The Puzzle Cabinet — authoring guide

How to add a kind of puzzle (an **engine**) and puzzles for it (a **family**).
Read this whole file, then read the reference engines `engines/jugs.js`
(a board you click and drag on, with a solver), `engines/tangram.js` (free
pieces that move, turn and turn over, checked against a silhouette) and
`engines/question.js` (typed or chosen answers, with figures), and their data
`data/jugs.js`, `data/tangram.js`, `data/ancient-riddles.js`, and generators
`tools/gen/jugs.js`, `tools/gen/tangram.js`.

Plain JavaScript and CSS, no build step, no libraries, no network at run time.
Everything must work offline from the files in `PUZZLES/`.

## Files

```
PUZZLES/
  index.html            the page (loads js/*.js, data/concepts.js, data/history.js, data/catalog.js)
  css/app.css           the look; theme tokens (see "Colours")
  js/cabinet.js         Cabinet: registry, rng, md(), store, h(), s(), css(), anim()
  js/geom.js            Cabinet.geom: vectors, polygons, placements, split, reflect, raster compare, congruence
  js/paper.js           Cabinet.Paper: a sheet that folds flat and is cut through all layers
  js/view3d.js          Cabinet.View3D: small 3D view (voxels, meshes, tubes, decals, picking, orbit)
  js/workbench.js       Cabinet.Workbench: the stage and all hand tools
  js/player.js          the puzzle page: hints, check, undo, save, stars, answer box
  js/library.js         home, shelves, families, eras, concepts, search
  js/lib/*.js           shared helpers loaded on demand (dlx.js = exact cover). Put new shared solvers here.
  engines/<engine>.js   one file per engine
  data/<family>.js      puzzle files (a family may span several files)
  data/concepts.js      concept pages (you may add concepts from your own data file)
  data/history.js       the timeline (you may add events from your own data file)
  data/catalog.js       GENERATED by tools/catalog.js — never edit by hand
  tools/load.js         loads everything in node
  tools/validate.js     checks every family and runs every engine's verify()
  tools/catalog.js      rebuilds data/catalog.js
  tools/selftest-browser.js   opens puzzles in the page, shows solutions, checks they count as solved
  tools/gen/<name>.js   generators that write data files (deterministic: seeded rng)
```

## Checks you must run

```
node --check engines/<engine>.js
node tools/validate.js --family <family>      # or --engine <engine>
node tools/catalog.js                         # only the lead runs this at integration; you may run it to test
```

`validate.js` loads **every** engine and data file, so a syntax error anywhere
breaks everyone: check your own files with `node --check` before leaving them.
A family whose engine throws at load time is reported as a load error.

Browser test (optional but valuable): the static server runs at
`http://localhost:8172/PUZZLES/index.html?nosw`. If you use the browser, open
**your own tab** (`tabs_create`, then `navigate` with that `tabId`, and pass
the `tabId` to every call) — other writers share the browser. Then:

```js
await new Promise((ok) => { const s = document.createElement('script');
  s.src = 'tools/selftest-browser.js?' + Date.now(); s.onload = ok; document.head.appendChild(s); });
PuzzleSelfTest({ family: 'your-family', limit: 30 });
// wait, then poll:
JSON.stringify(window.__selftest)
```

The page loads `data/catalog.js`, so your family only appears in the page
after `node tools/catalog.js` has run.

## A family (data file)

```js
/* The Puzzle Cabinet · data/matchstick-shapes.js — made by tools/gen/matchsticks.js */
Cabinet.family({
  id: 'matchstick-shapes',          // unique, lowercase-dashes
  engine: 'matchsticks',            // engine id
  cat: 'matches',                   // one of the shelf ids in js/cabinet.js (C.categories)
  name: 'Squares of matches',       // shown on the shelf
  about: 'How to play, for this family only (optional; else the engine\'s about is used)',
  order: 2,                         // position on the shelf
  blurb: 'Take away or move matches so that exactly the squares asked for are left.',
  origin: { year: 1893, who: 'Victorian parlour puzzles', note: 'One or two sentences of history, in our own words.' },
  concepts: ['invariant'],          // ids from data/concepts.js (or your own)
  deps: ['js/lib/dlx.js']           // optional: helper files the engine needs in the browser
}, [
  {
    id: 'match-sq-001',             // unique across the whole cabinet; start with a family prefix
    title: 'Three from Four',       // short, evocative, unique within the family
    diff: 2,                        // 1 Easy, 2 Fair, 3 Tricky, 4 Hard, 5 Fiendish
    year: 1917,                     // optional: when THIS puzzle was first published (curated classics)
    source: 'Dudeney, *Amusements in Mathematics* (1917), no. 211.',   // optional credit
    text: 'The statement (markup below).',
    goal: 'One line shown in a green box: what counts as solved.',   // optional; engines may set it with ctx.setGoal
    hints: ['First hint, gentle.', 'Second hint, stronger.'],       // optional, progressive
    explain: 'Why it works, shown after solving or revealing.',     // optional but encouraged for classics
    links: ['other-puzzle-id'],     // related puzzles (hyperlinks); must exist
    concepts: ['parity'],           // concept ids
    tags: ['remove', 'classic'],    // free words for search
    par: 7,                         // optional: fewest moves, when the engine counts moves
    data: { ... }                   // engine-specific
  }
]);
```

Text markup (`Cabinet.md`): `**bold**`, `*italic*`, blank line = new paragraph,
`[[puzzle-id]]` or `[[puzzle-id|label]]` links a puzzle, `[[c:concept-id|label]]`
a concept, `[[f:family-id|label]]` a family. Plain HTML tags `<b> <i> <sup> <sub> <br>`
pass through. Use Unicode for maths (×, ÷, −, ², √, ½, π, ≤).

**Ids never change once written** (progress is stored by id). Generated
puzzles: `<prefix>-001`, `<prefix>-002` … in a stable order.

## Words, sources, humour

- Write every statement, hint and explanation **in your own words**. Classic
  puzzles (Alcuin, Fibonacci, Bachet, Euler, Lucas, Carroll, Loyd, Dudeney,
  Hoffmann, Ball …) are public domain; retell them in modern English and credit
  the source in `source`. Never copy text from modern copyrighted books or
  sites (including Martin Gardner's): the *idea* of a puzzle is free, the
  wording is not. Say "popularised by Martin Gardner in …" where true.
- Do not invent history. If unsure of a year or attribution, leave `year` out
  and write a vaguer `source` ("a traditional puzzle").
- British or American spelling is fine; be consistent within a file. Metric
  units unless the source's units are part of the charm (pints, gallons).
- Humour: a light, warm touch in hints and explanations is welcome
  ("The goat has opinions about cabbage"). No sarcasm at the solver.
- Hints go from gentle to strong; the last hint should nearly give it away.
  Two or three hints for a typical puzzle. Generated puzzles may have no data
  hints if the engine gives live hints (`hint()` below).
- Difficulty honestly spread: every family needs easy ones first.

## An engine

```js
(function (root) {
  'use strict';
  const C = root.Cabinet, G = C.geom;

  C.engine({
    id: 'matchsticks',
    name: 'Matchsticks',                 // shown in "How to play"
    tools: ['select', 'pan', 'paint', 'pen', 'marker', 'eraser', 'note', 'xray', 'loupe'],
                                         // built-in tools to offer; add 'cut' / 'fold' when used
    workbench: { vertexSnap: true, rotStep: 45 },   // Workbench options (below)
    about: 'How to play, in markup: gestures, keys, what counts.',
    deps: ['js/lib/dlx.js'],             // optional helper files (also loaded by validate in node automatically if in js/lib)
    noMoves: false,                      // true hides the Moves counter
    movesLabel: 'Pours',                 // optional name for the Moves counter (also per puzzle: p.movesLabel)
    // (while a solution plays, the player offers a "Faster" button that speeds up C.anim durations)
    autoCheck: true,                     // false: only the Check button checks (e.g. "declare when done")
    textOptional: false,                 // true if puzzles need no text

    verify(p) {                          // NODE-SAFE: no DOM. Must prove the puzzle is solvable.
      return { ok: true } | { ok: false, err: '…' };   // may also return { ok: true, warn: '…' }
    },
    answerKey(p) { … },                  // only for engines answered through ctx.answer(): the value the self-test submits
    mount(ctx, p) {                      // BROWSER: build the puzzle on ctx.wb
      …
      return {                           // the instance
        check(manual) { return { solved: bool, msg: 'shown when not solved (manual)' }; },
        hint(n) { return 'text' | { text, show() { highlight on the board } } | null; },  // live hints, after data hints
        solve() { … },                   // show the solution (may animate); afterwards check() must say solved
        explain() { return 'text'; },    // optional, when p.explain is missing
        getState() { return json; },     // the engine's own state (NOT workbench pieces: those are saved automatically)
        setState(json) { … },            // restore it (undo, reload). Must redraw. Must NOT call ctx.changed().
        reset() { … },                   // optional extra reset work
        key(ev) { return true if handled; },   // optional keyboard (keydown AND keyup arrive)
        onSolved(r) { … },               // optional: the player has just counted the puzzle as solved
        destroy() { … },                 // stop timers, animation frames, listeners on window/document
        checkLabel: 'Done'               // optional label for the Check button
      };
    },
    thumb(p) { return '<svg viewBox=…>…</svg>'; }   // optional small picture for the family page (theme tokens OK)
  });

  C.css('matchsticks', `/* engine styles, using theme tokens */`);
})(typeof window !== 'undefined' ? window : globalThis);
```

Rules:

- The file must load in node without a DOM: only `C.css(...)`, `C.engine(...)`
  and pure functions at load time.
- `verify` must be deterministic, quick (well under 1 s per puzzle; aim for
  < 50 ms), and must really check solvability (run the solver, or check the
  stored solution against the rules). If puzzles are meant to have **one**
  solution (logic, Sudoku-like), verify uniqueness.
- After **every user action that changes the puzzle** call `ctx.changed()`.
  The player then saves, pushes an undo step and (unless autoCheck is false)
  calls `check(false)`. Actions on workbench pieces (drag, turn, cut, fold …)
  call it for you. Count moves with `ctx.move()` where moves are meaningful.
- `getState/setState` round-trip everything the engine owns. Undo restores
  both the workbench pieces and your state. Setting state must redraw.
- `solve()` leaves the puzzle solved (check() → solved). Animate with
  `C.anim(ms)` durations (the self-test speeds them up) and timers or
  `requestAnimationFrame`. When the animation ends, call `ctx.changed('solve')`.
- Never block: long searches in the browser must be bounded (hint searches
  on positions reachable from the current state are fine if small).
- Do not use `alert`/`confirm`/`prompt`: the player asks "Show the solution?" with its own card; for your own questions use `C.confirmCard` (below).

### ctx (what mount gets)

```
ctx.p                 the puzzle; ctx.family = family meta
ctx.wb                the Workbench (below)
ctx.rng               seeded random for this puzzle (C.rng(p.id))
ctx.say(msg, kind)    status line under the stage; kind '' | 'good' | 'warn' | 'info'
ctx.stat(label, v)    a counter in the status line ('Weighings', 'Cuts' …)
ctx.move(n?)          count one move (or set the count)
ctx.changed(why?, { undo: false }?)   after a user action (see rules); undo: false saves and checks without an undo step
                      (a wrong pick that stays crossed out, a found difference)
ctx.solved({msg})     declare solved now (for engines that know it without check)
ctx.setGoal(text)     the green goal box
ctx.answer(spec)      an answer box in the side panel (kind number|text|choice|multi; check(v) -> {ok, msg});
                      multi with allowNone: true adds a "None of them" button (question data: answer.multi = [] or allowNone);
                      check may return { ok, msg, stars } to cap the stars (e.g. after wrong tries);
                      spec.cls adds classes to the box for engine styling (e.g. a compact picture grid)
ctx.panel             an element in the side panel for engine controls (buttons, selects, legends)
ctx.button(label, fn, cls)   a button in that panel ('primary', 'gold', 'small', 'ghost')
ctx.hideText()        hide the side statement (when the stage shows it)
ctx.toast(msg)        a short message floating over the stage
ctx.sfx(name)         'snap' 'tap' 'cut' 'fold' 'pour' 'hint' 'wrong' 'solve'
ctx.h(sel, attrs, ...kids)   HTML element helper;  ctx.s(tag, attrs, parent)   SVG helper
ctx.md(text)          markup to HTML
ctx.isRevealed(), ctx.hintCount()
C.numberPad({ keys, onKey(k), cols, label })   a shared on-screen number pad element (put it in ctx.panel)
engine.stateVersion   bump it when your engine's layout or state format changes: older saved games are then not restored
handlers.pick(o, objs) may return false to refuse a drag (while an animation runs)
ctx.undo()            take back the last step (e.g. a "Take back my move" button)
ctx.hint()            ask for the next hint as if the Hint button were pressed (counts as a hint)
ctx.thinking(on, text?)   a small "Thinking…" pill over the stage while the computer chooses a move
ctx.keep(k, v) / ctx.kept(k, dflt)   tool settings (a cipher wheel's turn, a typed keyword): saved across reloads, not in undo
ctx.lockUndo(on)      block undo/redo while something is in progress (the computer thinking)
```

### The workbench (ctx.wb)

Coordinates are **world units of your choosing**; call
`wb.setBounds({x0, y0, x1, y1}, pad?)` once to frame the view (the user can
zoom and pan; `0` fits again). y grows downward (SVG).

Drawing your board: `wb.layer('bg' | 'board' | 'top')` are SVG groups in world
coordinates: `bg` under everything, `board` under pieces, `top` over pieces
(highlights, hint marks). Give any element a `data-key="unique-key"` attribute
and the **paint tool** can colour it (grouping by colour); call
`wb.applyPaints()` after you redraw such elements.

Free pieces (anything the user drags, turns, flips, cuts, stacks):

```js
const o = wb.add({
  id: 'm3',                         // optional; stable ids help
  kind: 'match', name: 'Match 3',   // kind = CSS class k-match; name for the Layers list
  shape: { poly: [[x,y],…] } | { rect: [w,h] } | { circle: r } | { path: 'M…', } ,   // local coords, centred on the piece's pivot
  type: 'match',                    // OR a registered type with a custom drawing: wb.type('match', { draw(g, o, wb), poly(o) })
  x, y, rot: 0, flip: false,        // placement (rot in degrees, clockwise on screen)
  fill, stroke, sw,                 // colours; the user may repaint (o.fill), your draw() should use o.fill when set
  move: true | false | 'x' | 'y',   // draggable (false: fixed, still clickable)
  rotate: false | true | 45,        // turning allowed (a number = step in degrees)
  flipable: false,                  // turning over allowed
  cut: false, fold: false,          // the knife / fold tools act on it
  remove: false,                    // the user may take it away (Delete key / trash button)
  snap: true,                       // ask handlers.snap while dragging
  hit: 0.2,                         // widen the clickable area (stroke width) — good for thin pieces
  label: 'A', labelSize: 0.5,
  data: { … }                       // yours; saved and restored with the piece
});
wb.update(o, { x, y, rot }, redraw?)   wb.remove(o)   wb.all()   wb.get(id)   wb.find(fn)
wb.worldPoly(o)                        // the piece's outline in world coordinates
wb.select([o])  wb.selected()
```

Handlers you may set on `wb.handlers`:

```
board: { down(pt, ev, el) -> true to capture, move(pt, ev), up(pt, ev), tap(pt, ev, el), hover(pt, ev, el) }
                       clicks and drags on the table (not on pieces) in the select tool;
                       hover is called while the pointer moves with no button pressed;
                       a RIGHT press on the table is offered to down() first (ev.button === 2), and pans if you return false;
       longpress(pt, ev, el, info)   a touch held still for about half a second (use it as the right click on phones);
                       also when your down() took the press (info.captured: undo what the press started, then mark)
Never use the browser's alert/confirm/prompt: `C.confirmCard(host, { title, text, ok, cancel })` returns a promise of true/false.
engine.about may also be a function (p, familyMeta) -> text; a family's meta.about overrides it.
Timeline events (Cabinet.history) and concepts (Cabinet.concepts) declared in your data files are collected
into the catalog, so they show on the history and concept pages before your files are opened.
snap(o, at, objs) -> {x, y}   position a dragged piece should jump to (grid, lattice, slots)
snapTargets() -> [[x,y]…]     extra corners pieces snap to (with workbench.vertexSnap)
toolSnap() -> [[x,y]…]        points the knife and fold lines snap to
settle(objs, why)             after a drag/turn/flip ends (tidy positions, then the player checks)
toolPoint(pt, g, ev) -> [x,y]   adjust the knife/fold drag end (angle steps…); g = { kind: 'cut'|'fold', a, b, crease }
toolPreview(g, wb) -> true      draw your own live preview of the knife/fold stroke in wb.layer('live')… (true = skip the default drawing)
hover(pt, ev, mode)             the pointer moves with no button pressed, in any tool
cut(a, b) -> false to let the default knife cut the pieces; anything else = you handled it
fold({a, b, side, from, to}) -> false if nothing folded; side +1/-1 = which side of a->b moves (0: you choose)
remove(objs) -> true if you handled the removal
pick(o, objs), dragging(objs)
```

Events: `wb.on('tap', ({obj, pt, ev}) => …)` (a click on a piece without a
drag), `wb.on('dbltap', …)`, `wb.on('change', ({why, objs}) => …)`,
`wb.on('select', objs => …)`, `wb.on('restore', …)` (after undo/reload: rebuild
anything you derived from pieces), `wb.on('view3d', is3D => …)`,
`wb.on('layout', ({ narrow }) => …)` (the phone layout was entered or left; `wb.isNarrow()` tells the current one).
`wb.fit()` keeps the board clear of the tool bar and the zoom bar, so no extra padding is needed.
`wb.zoomTo({x0, y0, x1, y1}, pad?)` opens the view on part of the board (e.g. the grid alone on a phone); `0` / fit still shows everything.
`ctx.button(label, fn, 'small gold')` — classes separated by spaces or dots.

Your own modes (tool buttons): `wb.addMode({ id, icon, title, key, down(pt, ev, el) -> true, move, up, hover, in3D })`,
then `wb.setMode(id)` to make it the current tool. Icons: names in `js/icons.js`
(add new ones there only through the lead; reuse existing names).

Floating actions for selected pieces: `wb.ctxActions.push({ icon, title, when(sel), run(sel, wb) })`.

`handlers.snap(o, at, objs)` may return `{ x, y, rot }` (rot turns the dragged piece too).
`handlers.settle(objs, why)` may return `false` when nothing really changed (a piece dropped back where it was): no undo step, no check.
A custom `hit` polygon is filled, never stroked; a numeric `hit` widens the piece's own outline by that stroke width.

`wb.raise(objs)` brings pieces to the top without an undo step.
Undo/reset (`wb.restore`) keeps the same piece objects for ids that survive, so references you hold stay valid (pieces created later by cuts are new objects — look them up by id or with wb.find).
`inert: true` on a piece: shown but never clicked (display-only cards, backgrounds). `inst.noMoves` overrides `engine.noMoves` either way.
`wb.setBounds(box, pad, { keepView: true })` updates the framing without moving a view the player has zoomed or panned.
Typing boards may take every letter key in `inst.key`: the player sends **Alt + letter** to the tool shortcuts first, so the tools stay reachable (mention it in your `about`).
`C.tween(ms, fn(t), done)` animates t from 0 to 1 (eased) and ALWAYS finishes, even in a hidden tab (timer fallback) — prefer it to raw requestAnimationFrame; returns a stop function. Pass durations through `C.anim(ms)`.

Options (`engine.workbench` or `p.workbench`): `snapOnDrop` (drag freely, snap to corners/targets when released, with a short glide), `modesFirst` (your own tool modes above the built-in ones; leave 'select' out of `tools` if you do not need it, and call wb.setMode(yours)), `keepView` (never refit on resize; a zoom the player chose already survives small resizes), `singleDrag` (drag only the grabbed piece), `selectFrame: false` (no dashed frame/turn handle), `ctxBar: false` (no floating action bar), `grid` (snap positions to a step),
`gridOffset`, `vertexSnap`, `snapPx`, `rotStep`, `cutMode: 'segment'|'line'`,
`toolGrid` (knife/fold points snap to this grid), `tools` (override).

The built-in knife cuts every `cut: true` piece the stroke crosses (or only
the selected ones) into new pieces (same style, `data.from` = old id). The
built-in fold mirrors the part of every `fold: true` piece beyond the crease.
For real paper (layers, unfolding) use `Cabinet.Paper` and handle
`handlers.fold` / `handlers.cut` yourself (see js/paper.js).

3D: `const v = wb.use3D({ onPick(hit, ev), down(hit, ev, pt) -> true, move(ev, pt), up(ev, pt, moved), after(ctx, view) })`
gives a `Cabinet.View3D` in the stage. `wb.set3D(true)` shows it; `wb.allow3D(true)`
shows the 2D/3D switch (listen to `'view3d'`). View3D: `v.voxels(cells, {id, gap})`,
`v.box(…)`, `v.add({verts, faces, colors, m, decals, doubleSided, alpha})`, `v.tube(points, r, color, {closed})`,
`v.poly(points, color)`, `v.fit()`, `v.render()`, `v.pick(x, y)`, `v.animate(ms, fn(t), done)`,
camera `v.cam = {yaw, pitch, dist, target}`; matrices `C.M4.rotate(deg, axis, point)`.
Decals draw on a face's unit square (v up the face): `{ text, color, size }` or `{ draw(ctx2d) }`.
Call `v.render()` after every change. More: `v.margins = { l, r, t, b }` (pixels the scene keeps clear of; fit and the projection centre honour it),
`v.cam.minPitch / maxPitch` (orbit limits), `v.cam.ortho = true` (orthographic camera; cam.dist still sets the size),
`opts.before(view)` (called at the start of every render), `mesh.faceBias[i]` (per-face depth nudge for the far-to-near sort), `v.ray(x, y)` → `{ origin, dir }` for dragging in 3D, and `v.animate(ms, fn, done)` returns a stop function and always finishes.
`tools: []` with no modes hides the tool bar; `engine.noPageNav: true` stops PageUp/PageDown from changing puzzles.

### Geometry (Cabinet.geom)

`add sub mul dot cross len dist norm lerp mid perp rot angle normDeg snapDeg`,
`place(p, t) placePoly unplace matOf svgTransform`, matrices `M.mul M.inv M.apply M.reflect M.rotate`,
`area(signed) absArea centroid bbox pointInPoly segDist segCross lineCross side clean convexHull isConvex`,
`splitPoly(poly, a, b, {segment}) -> [{poly, side}] | null`, `reflectPoly`,
`raster compareShapes(A, B, {align:'none'|'bbox'|'centroid', res}) -> {iou, missing, extra}`,
`overlapArea(polys)`, `segmentsCongruent(A, B, {tol, allowMirror})`, `pointsCongruent`.

Exact cover: `Cabinet.DLX.solve({ primary, secondary, rows, max, shuffle: rng, nodeLimit })`
in `js/lib/dlx.js` (add `deps: ['js/lib/dlx.js']` to the engine definition).

### Colours

Use the theme tokens so boards work in the night and day themes:
`--ink --ink-2` (lines, text on the board), `--board --board-2 --cell` (surfaces),
`--grid --grid-2`, `--wood --wood-dark --paper --paper-back --water --metal`,
`--accent --gold --teal --green --warn --red --pink --purple`, `--muted --faint --line`,
`--panel --panel-2 --text`. Real objects may keep real colours (a red match
head, gold coins). Piece palettes: `Cabinet.PALETTE`.

Text on the board: `font: 600 <size>px "Segoe UI", system-ui, sans-serif`.

## Generators

`tools/gen/<name>.js` writes one or more data files. Seed every random choice
(`C.rng(<number>)`), so re-running gives the same puzzles and ids. Verify
while generating (use your engine's solver) and keep only puzzles that pass.
Spread difficulty: order puzzles easiest first in the file. Keep data compact
(arrays over objects for bulk data). A family file should stay under ~400 KB.

## Endless drawers (strongly encouraged)

If your engine can make puzzles, give it a `generate` so its drawers get an
**Endless** mode: five level buttons on the family page that make a brand-new
puzzle on the spot (route `#/x/<family>/<level>/<seed>`).

```js
generate(rng, level, familyMeta) {
  // rng: seeded C.rng (same seed -> same puzzle); level 1..5 (Easy .. Fiendish)
  // familyMeta: the family's meta (id, name, …) — one engine may serve several families
  // return a puzzle WITHOUT id/family: { title, text, goal?, hints?, par?, diff: level, data }
  // or null if this attempt failed (the player tries the next seed)
}
generates: ['nim', 'kayles'],   // optional: only these families get Endless (default: all of the engine's)
endlessMs: 12000,               // optional: a heavy maker may ask for more than the default 6 s in total
```

Rules: it must run in the browser in well under a second (the player allows
6 s for up to 25 attempts), must be deterministic for a given rng, and every
puzzle it returns must pass `verify(p)` (the player checks before showing it).
Grade the level honestly (use the same measure as your generator: par,
search effort, clue count). Put the generator logic in the engine file (or a
js/lib file listed in `deps`), and let tools/gen/ reuse it with a fixed seed
for the stored puzzles. A family can opt out with `endless: false` in its
meta. Check it with:

```
node tools/validate.js --family <id> --endless 5     # 5 puzzles per level, each verified
```

See `generate` in engines/jugs.js.

## The self-test contract

For every puzzle, `PuzzleSelfTest` opens it and either submits
`engine.answerKey(p)` through the answer box, or calls `inst.solve()` and waits
until `inst.check(false).solved`. Make both paths work. No console errors.
