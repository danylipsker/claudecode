## Decisions
- **Repo `library\` as the default (Dany's pick)** over a fresh `library\live` subfolder or a named
  path. The consequence was accepted: the old 2026-09-14 snapshot shows in the list too.
- **Move, not copy (Dany's pick).** OneDrive originals were deleted only after hash checks. The
  deletes ran with the sandbox disabled, because sandboxed writes outside the repo are
  virtualized.
- **Found by walking up from the DLL, not a hard-coded path.** Same approach as
  `PyGearEngine.LocateServerScript`. The add-in is registered `/codebase` from its build folder,
  so the walk finds the repo; the `%LOCALAPPDATA%` fallback covers a copied-out DLL. Documents is
  never a fallback.
- **Registry (HKCU) for the saved choice, plus an env override.** It's per Windows user, needs no
  settings file, and `GEARGEN_LIBRARY` covers tests and one-offs.
- **Worktree guard respected.** This session was a claudecode worktree, and Edit/Write refuse the
  nested repo. The work was done in a copy inside the worktree, built there, then applied to the
  real checkout with Dany's OK. `git apply` could not be used: with core.autocrlf=true it
  rewrote the LF file `SwAddin.cs` wholly to CRLF, and with autocrlf=false it failed on CRLF
  files. A hunk-by-hunk exact-text applier was used instead, checked byte-for-byte by SHA-256.
- **Shared index with a concurrent session.** The Fibonacci session was committing in the same
  checkout. Staging collided once, when "you go first" messages crossed. Resolved by one session
  claiming the turn, waiting for an explicit ack, and staging only its own paths (shared README
  and PROGRESS via `git apply --cached` of our own hunks). The staged list was re-checked in the
  same command as the commit.
