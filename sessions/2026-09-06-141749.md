## Decisions
- Straight sides join sweeps only when tangent-continuous; a turn > 30° is a corner (except inside one curved segment, which is analytically smooth whatever the tessellation step). A long straight side next to a small kink is cut alone when the chord bow `L·Δ/8` would exceed 0.75 mm — pivoting a saw blade in place at a sharp corner is not modelled, and the classic cycle is right there.
- The straight approach is required only at a run's entry. Requiring it at every sub-side (the earlier per-segment planner did) is what made concave regions uncuttable; inside a run only the sweep pose matters.
- Blade body is modelled as W (edge distance) × D (in-plane depth from the Tool Selection window). The near face cannot be tested by side crossings — the outline behind the tip IS the kerf and lies on that line (my first version rejected every convex curve for that reason) — so the near side is probed a quarter blade-width inside the body at half and full depth. This makes the rigid-blade turning-radius limit explicit: an 8 mm-deep body refuses an R=20 concave fillet (and a 30° kink 3 mm behind the tip), a 2 mm body follows it. Physically defensible; the header tells the user which limit stopped a sweep.
- Elbow-over-blade-column check kept identical to the straight-side rule (reject unless the tool is "arm safe"). The user's tool 1 is arm-safe in the CSV, so it never limited anything in the tests.
- The first implementation of the direction fix recomputed the rotation from the reversed tangent, which flipped the placement by 180° and left the uncut end on the tool side; caught only because the driver reconstructs machine-frame positions from the recorded A/B/C poses via FK. Keep that reconstruction check in any future driver; the earlier 3-probe validity had passed sweeps whose orbit poses were never checked.
- Long runs: the "uncut end on the standoff side" check must be LOCAL (the next vertex after the entry), not the run's far end — a 270° sweep's far end legitimately sits above the blade line.
- One inner commit for the whole day (job feeds + transport + curves + planner), as per the repo's precedent; summary only in the outer repo.

## Open threads
- Round tools still cut as a bounding square (punch vs rotary blade question unanswered).
- The blade-body model has no kerf clearance parameter: W is both blade width and kerf. A "clearance" (set-teeth) value would let tighter concave radii pass for real jigsaw blades; currently the quarter-width inset stands in for it.
- Forward exit through the scrap at the end of a sweep (instead of retracting back through the whole kerf) is not implemented; retract always replays the kerf.
- Free curves are emitted as G1 pose chains, not fitted biarcs (G2/G3); a biarc fitter would compact those runs.
- Planner cost is O(runs × n² × 4) with cached poses; fine to ~1000 sub-sides, untested beyond.
- Scratch drivers (CurveMotionDriver, LoopSweepDriver in the session scratchpad) are not committed; CurveMotionDriver's per-segment expectations are obsolete.
- ARCHITECTURE.md still lacks View3D / Aug-26 editor / round tools / Tools Table / transport chapters (transport is mentioned only in §5's file list).
