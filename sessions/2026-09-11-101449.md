## Decisions
- One reset button, labelled for the selected card, rather than a button in every family
  section: each kind has its own defaults but only one kind is ever selected, and the label
  says which one will be reset.
- Defaults live in `GearParameters.CreateDefaults` as the single source (the class initialisers
  are the spur defaults; each card overrides what makes it sensible, matching the values the
  card-selection methods already jump to); `CopyFrom` copies by reflection so a parameter added
  later can't be missed; a blanket `PropertyChanged("")` refreshes every binding.
- Edges come from the tessellated preview mesh by crease angle rather than from B-rep edges
  exported by the Python side: no protocol change, and the crease threshold naturally leaves
  tangent-continuous fillet boundaries silent, which a B-rep edge list would draw. 30° was chosen
  from measured facet angles — the tightest previewed curve (a 3 mm rack hole at the 0.02 mm
  preview tolerance) reaches ~19°, real corners (tooth tips, rack flank-to-land, end-face
  outlines) are 55°+.
- Light ground with a mid-blue gear (the CAD-viewer convention) instead of tuning the dark
  ground: the pale gear on the dark ground shaded almost flat, every face the same tint.
- Yesterday's open thread about the planetary preview reading as one flat disc is closed by the
  edges — no per-body colouring needed.
- The GitHub device-code login (`gh auth login --web`) was started for the user twice (codes
  76A1-EE53 and 3C49-CE26, page opened, code on the clipboard) and lapsed after the 15-minute
  window each time; the authorization is the user's to do on github.com, and a third unattended
  code would only expire the same way, so it was not retried.
