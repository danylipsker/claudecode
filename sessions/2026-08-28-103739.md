## Summary

Short follow-up to this morning's CURVES session: the lab gained a vector-export
section. One click now saves the selected curve as SVG, DXF (R12), PDF, EPS, AI
(Illustrator-3 PostScript), WMF, EMF or HPGL — all generated in-page with no
libraries — alongside the existing PNG canvas capture. The two binary metafile
writers were validated by having GDI+ (the engine Office itself uses) load and
render the produced files; the WMF drew a pixel-perfect astroid.

## What changed

- New **Export** section in the control panel with nine buttons and a note
  explaining what each format carries (CURVES/CURVES.html).
- `exportFigure()` extracts the exportable geometry once: world-space polylines
  (`segs3`) plus flat y-up polylines (`segs`), split at NaNs, at points beyond the
  robust-bbox limit, and at world-space jumps of >35% of the curve span — so
  asymptotic branches (hyperbola, conchoid…) export as separate polylines instead
  of joining across infinity.
- Format builders: `buildSVG/PDF/EPS/AI/DXF/HPGL` emit text; `buildWMF/EMF` emit
  bytes through a small little-endian `BW` byte-writer class. All share
  `layoutSegs()` (fit into a page with margin, optional y-flip). Black stroke,
  tightly cropped, full sample resolution.
- `robustBBox()` now also returns its outlier `limit` so export and rendering
  share one notion of "too far to be real".

## Decisions

- **DXF always carries true world coordinates** — real 3D POLYLINEs (flag 70=8,
  vertex 70=32) for space curves — because CAD/CNC is the one consumer that wants
  the mathematics, not the picture. R12/AC1009 with POLYLINE+VERTEX was chosen
  over LWPOLYLINE for maximum reader compatibility.
- **Flat formats export what the current view shows**: a space curve in 3D mode
  exports its screen projection, in 2D mode its xy projection; planar curves
  always export world xy. Rationale: a flat file can't hold z, so "what you see"
  is the only non-arbitrary answer, and it matches the on-screen HUD wording.
- **AI is written as Illustrator-3-format PostScript** (m/L/S/w/G operators with
  AI DSC headers) — the classic pre-PDF .ai dialect that Illustrator still opens.
  If some app rejects it, EPS/SVG/PDF carry identical geometry.
- **WMF is a placeable metafile at 1000 units/inch (~8000-unit drawing)** — the
  format is inherently 16-bit; precision is bounded but invisible at that scale.
  EMF is the higher-precision sibling. PDF is hand-assembled with an exact xref
  table (offsets verified by re-parsing).
- **HPGL (.plt) was added beyond the requested list** because Dany's NOVELTECH
  work involves cutting machines — `PU`/`PD` polylines at 0.025 mm units.
- **Verification without a visible pane, again**: the pane loads the app on a
  data: origin which Chrome blocks from fetching localhost (a Node loopback
  save-server was built, worked from curl, but the page couldn't reach it). The
  working method: a Node harness that slices the builder functions *out of the
  shipped CURVES.html* by marker comments and eval's them — so the exact shipped
  code produced the test files (byte-identical sizes to the in-page builds), then
  GDI+ rendered the WMF/EMF, headless Edge rendered the SVG, and the PDF xref was
  re-parsed. Manual base64 transcription of canvas dumps was already ruled out
  yesterday (corrupts); this harness pattern is the reusable answer.
