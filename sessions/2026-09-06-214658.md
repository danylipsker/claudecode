## Summary

Short follow-up to the big VectorLab session closed at 21:25 (`sessions/2026-09-06-212531.md`).
Its first open thread — "the morph is static" — is now closed: morph steps are live and
regenerate whenever either end shape, or the spine, changes. Verified in the in-app browser with
ten scripted checks (move, reshape, restyle, cache, rebuild, duplicate, break apart, delete an
end, bend the spine, undo). This commit also carries three session-file moves that a parallel
session had staged (see Decisions).

## What changed

- **Live morph** (`VECTOR-EDITOR/vector-editor.html`): each in-between shape carries a blend record
  `{a, b, t, spine, turn}`; `refreshBlends()` runs before every render and regenerates the steps
  from their ends when a signature of either end (matrix, nodes, holes, closed flag, style) or of
  the spine has changed. Dragging an end re-blends every frame; an untouched blend costs one
  string compare per render.
- Pressing Morph with a step selected, or with the same two ends, rebuilds the blend in place and
  keeps its group; changing the step count while a step is selected does the same.
- Break apart and Ungroup freeze the steps into ordinary shapes. Deleting an end freezes its steps
  instead of deleting them.
- Duplicating a whole blend yields a copy that is live between the copied ends; a partial copy
  freezes. JSON import remaps the links the same way (`remapBlends`).
- `cloneShape` copies the blend record so undo never freezes a live blend; the signature cache is a
  `_bsig` property, so it is never saved and never survives an undo clone.
- Panel hint and button titles updated to say the morph is live.

## Decisions

- **Re-blend on render, not on edit.** Every edit path already ends in `render()`, so hooking there
  covers node drags, handle drags, transforms, style changes, undo and import without touching any
  of them. The signature compare keeps the cost negligible when nothing relevant changed. Two
  passes per render so a blend whose end is itself a blend step settles.
- **Steps are overwritten, not protected.** Editing a step directly is allowed but undone by the
  next change to an end. Illustrator locks them; here Break apart is the explicit "I want to edit
  these" gesture, and it is one click.
- **Ungroup releases the blend.** Users expect ungrouping to free things; keeping steps live after
  ungrouping would be surprising. Break apart is the same operation with a clearer name.
- **A missing end freezes rather than deletes.** Deleting a shape should not silently delete six
  others.
- **Included the parallel session's staged renames.** On close-out the index already held three
  moves of older session summaries into the root `sessions/` folder (from "Linear Half Tone" and
  "sokoban"), staged by another session that had just committed a consolidation of that folder.
  They are pure renames of markdown files and match that session's intent, so they ride along in
  this commit rather than being left half-done in the index.

## Open threads

- Blend profile is baked into each step's `t`; to change the profile you press Morph again. A
  stored profile name would let the profile dropdown re-space a selected blend live too.
- The blend regenerates style as well as geometry, so a step cannot keep its own colour. If that
  is wanted, the record needs a "style locked" flag.
- The remaining open threads from `sessions/2026-09-06-212531.md` still stand: tracer corner
  rebuild treats roundings under ~3 source px as sharp, photo tracing is posterised, `resizeSel`
  anchors top-left in Y-up documents, layout persistence verified by code path only.
