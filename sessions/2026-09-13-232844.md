## Decisions
- **Foreground is the root cause of the import hang**, established by a home-grown StackWalk64 stack dumper (main thread parked in `su_CDialog::DoModal` in the ACIS translator, body already imported, no visible dialog). Ruled out the diagnostics prompt, 3D-Interconnect choice, WPF/async nesting, and worker-thread marshalling (which only added `InvalidCastException`s) before landing on foreground. Automation-launched SolidWorks is exempt, which is why the standalone exporter never hit it.
- **The add-in can only be tested from inside itself.** An automation-launched SolidWorks skips startup add-ins and a normally started one isn't in the running-object table, so `--swloadaddin`/`--swaddincheck` are not valid startup-load tests. Kept a `GEARGEN_ADDIN_SELFTEST` in-process hook (timer-driven, with a re-entrancy guard because `LoadFile4`'s modal loop pumps the WinForms timer) as the verification path.
- **The self-test/pane hooks are env-gated debug scaffolding** left in on purpose: they never run without the flag and are the only way to exercise the add-in headlessly.
