# Session — 2026-10-05 09:25

**Branch:** main · **Commit:** 34b081c

## Summary
A follow-up to the Hyper ESP32 build session of the same morning (`2026-10-05-053104.md`). That session ended with
71 C++ programs not compiled because their libraries were missing. Dany gave three folders off OneDrive for the
purpose (`C:\arduino`, `C:\arduino-adafruit`, `C:\arduinoData`) and said to install what was necessary. The count
went from 543 to **609 of 620 programs built, none failing**; the new builds exposed three more real errors, which
were fixed in the pages.

## What changed
- **The compile tool can work from other folders** (`HYPER-CORE/tools/compile-esp32.js`): `--sketchbook <dir>`,
  `--data <dir>` (a second Arduino data folder, so another core version) and `--libraries <dir>[,<dir>]`. They are
  passed to arduino-cli through environment variables; its own settings file is never changed. The report now
  always covers every program, even when `--only` limited what was built (a partial run had overwritten
  `COMPILED.md` with a partial report). A program that includes the reader's own trained-model header is listed as
  "needs a file of your own" instead of "library missing". A single build may take 45 minutes (the audio library
  needed more than 15).
- **The two MAX7219 programs no longer use the LedControl library** (`content/alphanumeric-displays.js`). It
  includes an AVR-only header and does not compile for the ESP32. Their C++ now writes the chip's registers over
  SPI, as the block and MicroPython versions already did; the text, library line, notes and sources say so.
- **A global array `bars` renamed `cells`** in the custom-characters program (same file): it collided at link
  time with a symbol inside the Wi-Fi libraries.
- **The internet-radio program says to choose the Huge APP partition scheme** (`content/audio.js`): with
  ESP32-audioI2S it is about 1.9 MB and does not fit the default one.
- **The five Arduino_GFX programs tell the reader to keep the library up to date** (`content/graphic-displays.js`):
  version 1.6.4 builds with core 3.3.3 and not with 3.3.7.
- **`API-CRIB.md` Appendix C** records these four findings for future writers.
- **`COMPILED.md` regenerated**: 620 programs — 609 built (1 only with Huge APP, 7 as one part of a sketch,
  5 with core 3.3.3), 3 need a library that exists only on GitHub, 2 need a newer core, 6 are for other boards or
  need the reader's own file, 0 failed.

## Decisions
- **Installed into `C:\arduino\libraries`, not the OneDrive sketchbook.** Dany does not use OneDrive and the real
  sketchbook there holds cloud-only folders that cannot be read. With his "yes, do what is necessary" I installed
  21 libraries and their dependencies from the Arduino Library Manager: PubSubClient, OneWire, DallasTemperature,
  RadioLib, LiquidCrystal I2C, Async TCP, ESP Async WebServer, M5Unified (+ M5GFX), DHT sensor library,
  XPT2046_Touchscreen, LedControl, GxEPD2, RF24, TM1637, MD_Parola (+ MD_MAX72XX), NimBLE-Arduino, AccelStepper,
  Simple FOC, Painless Mesh (+ TaskScheduler), MFRC522, ESP32-audioI2S. LiquidCrystal went into
  `C:\arduino-adafruit\libraries` because the copy in `C:\arduino` is an empty shell and nothing was deleted.
  The Arduino IDE sees these only if its sketchbook location is set to `C:\arduino`.
- **Only Library Manager libraries were installed.** Three programs need libraries that exist only on GitHub
  (ESP32-A2DP twice, ESP32-BLE-Keyboard). I said beforehand I would leave those out unless told otherwise, and did.
- **The Arduino_GFX programs were built with the older core in `C:\arduinoData` (3.3.3)** rather than left
  unbuilt: the installed library release and core 3.3.7 do not fit each other, and the report says which core
  each of those five was built with.
- **LedControl was replaced, not patched.** A reader installing it from the Library Manager would meet the same
  failure, so the page should not depend on it; writing five registers over SPI is short and shows what the chip
  does.
- **No newer core was installed.** The two Matter programs need core 3.3.12 or later; that is a download of
  several hundred megabytes into Dany's Arduino data folder, so it is left for him to decide.
