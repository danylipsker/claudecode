## Decisions
- **Verified by measurement, not just the formula.** Near the cutoff the undercut grows
  as the CUBE of the overshoot: a tooth below it the cut is sub-micron (0.4-0.6 um at
  45deg z = 6). A production-resolution polygon sweep can't see it, so the onset was
  pinned with exact kinematics: the cutter's points carried through
  `rack_point_to_gear_frame` at 40000 roll steps, then cut^(1/3) fitted linearly in z.
  It agreed with the formula within 0.3 % at every angle and shift. The spur case shows
  the same -0.3 %, so that is the fit's bias. The tests use n_phi = 2000 sections, where
  0.4-0.6 um vs < 0.2 nm is a robust margin.
- **6.752, not the 6.77 quoted in the request** (old: 9.549, not 9.57) -- the tests pin
  the exact value.
- **No C# change.** `GearDerivedValues.QuickEstimate`/`QuickWarnings` has no callers and
  never reads `HelixAngleDeg` (its pitch diameter uses the normal module too), so it is
  spur-only by construction.
- **The generator errors went to a separate session rather than into this fix.** Each
  one changes nearly every family's geometry, and the main checkout had other sessions'
  work in progress.
- **At the merge, the fix moved INTO main's new `undercut_cutoff(gp)`** (from the
  screw-pair patch) instead of staying inline, so the screw pair's gear 2 is corrected
  too.
- **Strain wave: the test expectation was wrong, not the ring.** The notch fix left
  `test_strain_wave`'s 30deg / k = 1.1 case at 8-10 % of teeth in contact against a 15 %
  floor. The rings are the envelope of the flexspline's own tooth, so they still fit
  (overlap 0, the lobe tooth within 1.6 um of both ring flanks). Every lost contact (the
  teeth at +-10.8 and +-14.4deg from the lobe) sat at -0.65..-0.75 m, on the notch's
  imprint below where the old involute began; those teeth now clear the ring by 13 and
  26 um. I drafted a per-case floor, then discarded it: 1f8be94 had already changed the
  test to "three teeth per lobe" on the same diagnosis (another session flagged it), and
  a competing edit would only conflict.
- **Never touched the main checkout's working tree, except clean fast-forwards.**
  Merges happened in the worktree, and the docs commit was cherry-picked onto a moved
  `main` in a throwaway worktree, so the source files under a running test suite never
  changed.
