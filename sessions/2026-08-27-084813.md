## Decisions

- **Curves never cross the editor boundary.** OK tessellates to the same `List<Point>` the
  simulation/G-code/3D view always consumed — a curved side becomes many short straight
  sides. Rejected the alternative (teaching SimulationEngine about curves) as a huge,
  risky change for zero machine-side benefit. Consequence to watch: the cutting animation
  iterates per side, so very curvy shapes mean many more sides (see Open threads).
- **NURBS = control-point semantics on purpose.** A run of consecutive NURBS edges is one
  rational cubic B-spline whose control points are the run's vertices (weights pull; the
  curve does not pass through interior vertices). That is what NURBS means; interpolating
  alternatives (fitting) were rejected as false advertising.
- **"Twisted" defined as angle-offset preservation** (rotating one handle rotates the other
  by the same delta, lengths free) — the requirement named it without defining it; this is
  the coherent "linked but bent" reading, documented in tooltips and ARCHITECTURE §9.
- **Grabbing a Smooth (auto) handle converts the vertex to Asymmetric** — standard vector-
  editor UX; auto handles otherwise recompute and would fight the user's drag.
- **Missing handles are lazily seeded with the exact fallback the geometry would use** —
  found during review: a zero-length handle put its knob on the vertex dot and stole the
  vertex's hit test (knobs are tested first). Seeding preserves the curve bit-for-bit.
- **Corner pass operates on per-edge polylines with an explicit continuation point.** The
  test harness caught the one real bug of the session: edge lists exclude their end point,
  so the outgoing path at a corner measured zero length and the treatment silently no-oped.
- **Verification by compiled harness, not by hand:** csc test exes referencing the built
  app exe, run from `bin/Debug` (assembly resolution), plus an in-process WPF driver using
  reflection + `RenderTargetBitmap` for real screenshots off-screen. `DialogResult` on a
  non-modal window throws — caught deliberately after `GeneratedPolygon` is populated.
- **Left uncommitted:** `obj/Debug/*.AssemblyReference.cache` churn (build noise; prior
  sessions did the same) and the pre-existing untracked `ARCHITECTURE.pdf` (stale-prone
  export; GitHub renders the Mermaid, so the .md is the artifact that matters).
