Hyper Driving's service worker deleted the offline caches of every other app on the site whenever
it updated. The fix is pushed and live on GitHub Pages.

## What changed

- On activation, Hyper Driving's service worker now deletes only caches whose names start with
  `hyper-driving-`. Before, it deleted every cache not named `hyper-driving-v1`. Every app on
  danylipsker.github.io shares one cache store per origin, so each Hyper Driving update also wiped
  Sokoban's `sokoban-v1` (HYPER-DRIVING/sw.js)

## Decisions

- **The cache name stays `hyper-driving-v1`.** Only the prefix filter changed. Changing the worker's
  bytes is enough for browsers to install the new version, and a new cache name would have made
  every user download the whole app and content pack again for no gain.
- **The fix protects Sokoban from the first update on.** The deletion runs in the *new* worker's
  activate handler, so the old version never runs its broad cleanup again.
- **Convention for future apps:** any app on this site that gets a service worker must name its
  caches `<app>-vN` and delete only its own prefix, as sokoban/sw.js and HYPER-DRIVING/sw.js now
  both do.
- **Verification:** on the local apps server (one origin, both apps), I seeded `sokoban-v1`, a
  decoy `other-app-v1` and a stale `hyper-driving-v0`, then loaded Hyper Driving. After its new
  worker activated, the first two were still there, `hyper-driving-v0` was gone, and
  `hyper-driving-v1` refilled with 190 files. The live Pages copy of sw.js was then confirmed to
  hold the fix.
