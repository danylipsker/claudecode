- `DOC_SCHEMA = 2` with `DOC_KEY` / `DOC_BAK` constants. A stored document with no `v`

- `docJSON()` stamps `v`, so both the autosave and exported `.json` carry the version.
- `load()` branches on it: newer than this build → refuse; older → migrate; unparseable →
  give up. All three copy the original to `vectorlab.doc.bak` first, with a timestamp and
  reason, and set `docLoadNote`.
- `migrateDoc()` defaults `sh.m` and drops malformed `subs` / `g` — the two fields earlier
  summaries named as the actual legacy risk.
- `loadJSONFile()` applies the same rules to imported files: a newer file is refused with a
  message and the drawing already open is left untouched; an older one migrates and says so.
- `boot()` shows `docLoadNote` in the status bar instead of the generic greeting.

## Decisions

- **Rejected the obvious `if (d.v !== 1) return false`.** In this app that guard destroys
  the thing it protects: `boot()` runs `if (!load()) sampleDoc()`, and `save()` fires 400 ms
  after the next edit, so a refused document is replaced by the sample and then overwritten
  for real. The backup copy is the only thing standing between a refusal and data loss, so
  it is written *before* anything else can touch the key. Costs ~20 lines more than the
  naive version; the naive version is a footgun.
- **Current schema is 2, not 1.** Making "no `v`" mean 1 and current mean 2 keeps legacy and
  current distinguishable without ambiguity.
- **Versioned `docJSON()` rather than only the localStorage payload**, so the autosave and
  the exported file share one format and both import paths (`load`, `loadJSONFile`) can
  check it with the same rule.
- **A newer imported file is refused without disturbing the open drawing** — unlike the
  autosave there is no copy to keep, but the file on disk is untouched, so refusing costs
  the user nothing.
- **Verification method, for the blocker that defeated four sessions:** the preview pane
  serves the app from a `data:` origin where `localStorage` throws `SecurityError`. Rather
  than stub the logic in Node, I shadowed `window.localStorage` with a working in-memory
  stub via `Object.defineProperty` and exercised the *real shipped* `load`/`save`/
  `migrateDoc`/`backupDoc` against six scenarios (empty, current, legacy, v99, corrupt,
  round-trip) plus three `loadJSONFile` imports with real `File` objects. All passed; the
  v99 case preserved the original byte-for-byte. **This is the reusable answer to the
  data:-origin storage problem.**
- **A console error I first attributed to the parallel session's ruler code was mine.** My
  test fixtures used shapes with no `style` object, which real shapes always have, and the
  tab had kept the fake storage instead of getting a fresh JS context. A clean headless Edge
  run boots correctly with all 8 sample objects, rulers and panels. Worth remembering: after
  injecting fakes, re-verify in a genuinely fresh process before blaming anyone else's code.
