## Decisions

- **Boolean geometry will be flatten → clip → refit, not exact arc-preserving.** Three of the four
  pipeline stages already exist and ship as part of text-outlining (`simplifyLoop`, `loopToNodes`,
  and the even/odd nesting classifier inside `traceText`), so only the clipper itself is new. The
  cost is that arcs come back as cubics, so DXF loses exact arcs on booleaned curved shapes.
  Crucially this is *not* a general approximation: when every input segment is already a line
  (rectangles, polygons, stars) there is no flattening error and the result is emitted exactly.
- **The clipper will be Martinez-Rueda, not Greiner-Hormann.** Greiner-Hormann is smaller and
  tempting, but it breaks on shared and collinear edges — and with grid snap on, axis-aligned
  rectangles make that the *common* case here, not an edge case.
- **Groups are a path string on a flat array, not a nested tree.** A true tree is the "correct"
  model but would rewrite z-order, hit testing, `reorder`, and rendering. The path string buys
  nesting for almost nothing.
- **Difference keeps the bottom-most shape** and inherits its style, matching Inkscape/Illustrator
  "Minus Front". Z-order is stable and visible, and the existing front/back buttons already let you
  choose which shape is the subject.
- **Correcting an earlier call in this session:** the start-of-session briefing recommended
  *avoiding* booleans as "substantially larger than everything else combined". That was written
  before reading the geometry core and was wrong — `sh.subs` + `evenodd` already models holes, and
  `explodeTextShape` is a working template for constructing a boolean result. The job is much
  smaller than that briefing implied.

  worth copying into the repo if it should survive.
- Planned UI, per the user: union / difference / intersect / group / ungroup as icons in the **left
  tool palette only** — nothing in the top bar or right panel. These are actions, not modal tools,
  so `buildToolbar` needs to accept an `{act: fn}` entry alongside `{k: toolKey}`, and action
  buttons must never take the `.active` class.

  future change to the shape model will half-load an old autosave and then overwrite it on the next
  edit. Adding `v: 1` and refusing unknown versions is cheap insurance and is *more* urgent now that
  `g` has been added to the model.
- A baseline copy of the editor as it stood before this session's edits is in the scratchpad at
  `vector-editor.BASELINE.html`; it can be deleted now that the file is committed.
