## Decisions

- **Corrected the documentation, not the circuit, for circuit 01.** Restoring a keyed
  trigger button would have contradicted the scan-fidelity goal — the book page may
  not draw one. The auto-triggering source is a legitimate design choice; only the
  prose describing it was wrong.
- **Fixed the on-canvas text as well as the README.** Fixing only the README would
  have left the identical false instruction drawn under the schematic, where a reader
  is far more likely to see it. Circuit 06's "Press T" was deliberately left alone —
  it genuinely has `key="t"` and passes the key gate.
- **Waited for quiescence before committing the parallel session's work.** Its last
  write was 07:41:58 and the close-out ran at 08:27, so 45 minutes idle. Committing
  mid-pass risked capturing half-written files.
- **Staged selectively while that session was still active.** Earlier in the session
  its new README section was interleaved with this session's one-line row change, so
  the diff was split and only the intended hunk applied to the index, rather than
  `git add -A` sweeping in unfinished work.
- **Did not re-apply the circuit-24 fix a sixth time while the writer was live.**
  Patching an output file that is being actively regenerated just loses the race; it
  was re-applied only once the tree went quiet.

## Open threads

- **Two files regress on every regeneration, and both were caught again at close-out.**
  Circuit 24's duplicate `key="l"` has now been clobbered five times; circuit 01's
  corrected on-canvas text was reverted once, restoring the "Press T" instruction to a
  circuit with no switch. In both cases the regenerated file differs from the committed
  version by *only* that one defect — so the generator is otherwise producing the right
  circuits, and two one-line changes at the source would end this permanently. Until

  be 1, and `grep -c 'Press T' 01-*.txt` should be 0.
- **`lint.py` is the natural home for a duplicate-key rule.** It already checks
  layout traps that fail silently; "two `li`-linked switches sharing a `key`" is
  exactly that class of bug — the key goes inert with no error. Adding that check
  would catch the regression above automatically instead of relying on a manual gate.
- **The verification gate is still not checked in.** It lives as ad-hoc JavaScript
  driven against a local same-origin mirror. The fast form needs no timers at all —
  `importCircuit` and `toggle()` are synchronous, so element counts and switch
  positions read back immediately, and all 28 circuits verify in ~560 ms. Only the
  solver-health check needs real wall-clock time. Worth committing next to `lint.py`.
- **Browser throttling still applies to any timer-based sweep.** Chrome throttles
  long-hidden pages hard (a 100 ms timer measured at 976 ms) and the simulator's own
  timer with it. Reload resets the clock; better still, avoid timers as above.
