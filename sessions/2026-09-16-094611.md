## Summary
Built GALAXIES, a browser implementation of the puzzle Nikoli publishes as Tentai Show
and Simon Tatham's collection calls Galaxies, which Dany plays daily. It generates its
own puzzles, proves each one has a single solution, and gives hints that explain the
deduction in words. The repository root became a small launcher page so the game is
reachable beside VectorLab, and a static server script was added so that page can be
tried locally. Everything is on origin/main across three commits.

## What changed
- New puzzle engine: constraint solver over per-cell galaxy candidates, generator,
  difficulty rating, Tatham-compatible game-ID codec, board analysis and a hint finder.
  Runs unchanged in the page, in a Web Worker and in Node (`GALAXIES/galaxies-core.js`).
- New interface: canvas board, galaxy painting with automatic mirroring, boundary-line
  drawing, hints with an Apply button, mistake checking, daily puzzle, share links,
  undo/redo, pause, statistics, light and dark themes, resume after reload
  (`GALAXIES/galaxies-ui.js`, `GALAXIES/index.html`, `GALAXIES/galaxies.css`).
- Two Node test harnesses: generator checks for uniqueness, solution validity, ID
  round-trip and timings (`GALAXIES/tools/bench.js`), and a run that solves puzzles using
  only the hint engine and verifies every step (`GALAXIES/tools/hints.js`).
- The site root stopped redirecting into VectorLab and now lists the browser apps
  (`index.html`).
- A static server for the repository root, so the apps page and its links work locally
  (`scripts/serve.js`), registered in the launch config beside the game-only one
  (`.claude/launch.json`).

## Decisions
- **Wrote a new engine rather than porting `galaxies.c`.** Read Tatham's source through
  Chris Boyle's sgtpuzzles repo for the rules, controls and game-ID format, then wrote
  the solver and generator fresh in JavaScript. The game-ID format is matched exactly, so
  codes move both ways between this and Tatham's version, including his `10x10dn:` style
  parameter suffix.
- **Painting galaxies is the primary interaction, not drawing lines.** The 180° mirror is
  the heart of the puzzle, so claiming a cell fills its mirror automatically. Boundary
  drawing is kept as an equal alternative for players used to the classic input; the two
  mix, because a border between differently painted cells counts as a wall.
- **The board starts empty.** Pre-filling the cells that touch each dot is forced by the
  rules and was the first default, but it made the opening board busy with automatic
  borders. It is now a setting, off by default.
- **Solver search propagates at level 2, not level 1.** Doing the connectivity-forcing
  deductions inside the uniqueness search costs more per node and prunes far more: on a
  20×20 grid the check went from 5.2 s to 121 ms. Level 3 inside the search was tried and
  is slower per node, so it is used only for rating.
- **The generator works to a time budget and will settle for a near miss.** Rather than
  search unbounded, it holds a 15 s budget with shorter per-check deadlines, and after
  35% of that budget it accepts a puzzle one step off the requested rating. The interface
  says so when it happens, rather than silently mislabelling.
- **Difficulty is measured, not assumed:** each puzzle is graded by the strongest rule the
  solver needs. Note the ladder differs from Tatham's. Level 2 here is roughly his Normal;
  the Easy tier here is below anything he offers, which is why Easy is unreachable on
  large grids.
- **The root redirect had to go.** It jumped into VectorLab after zero seconds, so a link
  added to that page would never have been visible. Replaced with a two-item launcher,
  VectorLab first. Dany was told the behaviour changed and can have the redirect back.
- **`scripts/serve.js` is separate from `GALAXIES/tools/serve.js`.** The game folder keeps
  its own server so it stands alone if copied elsewhere; the root one serves the whole
  repository, which is what the apps page needs.
- **`.vs/` was left out of every commit.** It is tracked already and churns several
  megabytes of Visual Studio index databases on every IDE run. Committing that adds
  nothing, and untracking it is a repo-wide change that was not this session's business.

## Open threads
- **20×20 rates one step harder than requested** (Easy comes out Normal, Normal comes out
  Hard) and takes 5 to 15 s to generate. This is inherent: 400 cells rarely all fall to
  the simplest rules. Tested against several growth parameter sets and none fixed it.
  Documented in the README and surfaced in the interface. Smaller grids hit the requested
  rating exactly and generate in under a fifth of a second.
- **`.vs/` is tracked and dirties the tree every session.** Worth a `git rm -r --cached
  .vs` plus a `.gitignore` entry, but that rewrites what the repo tracks, so it should be
  a deliberate decision.
- **The apps page lists only VectorLab and Galaxies.** Other browser things in the
  repository (sokoban, tic-tac-toe, the G-code viewer and simulator, CIRCUITS, CURVES,
  Linear Half Tone) are not linked yet.
- **Untested on a real touch device.** Touch targets were widened for dots and the layout
  was checked at 375 px in the browser pane, but not on actual hardware.
- **No sound and no animation settings.** There is a win celebration; someone who wants it
  quiet has no switch.
