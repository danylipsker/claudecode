## Decisions
- Threads are not modelled (nominal-diameter cylinders with a run-out chamfer), the usual CAD
  library convention; nut bores at nominal d. Recesses (hex, hexalobular, Phillips) are
  representative solids, not gauge geometry.
- Each geometry is generated once with the family's default property class (sets STEP colour
  and name); other classes are generated on demand and get the class in the file name
  (`ISO4762_M6x20_A2-70.step`). Masses for 7 materials live in `index.csv`.
- DIN designations with identical ISO geometry (912, 913, 916, 965, 7985, 7991, 125 A, 9021)
  are generated as separate files so names carry the DIN number, at the cost of duplicate STEP.
- The STEP files (~205 MB) are committed to the fasteners repo (each file is small); `custom/`
  and .NET build output are ignored.
- Add-in compiled against the SOLIDWORKS 2020 interop by default (oldest installed >= 2020, loads
  in every newer release); registration is global for all installed versions.
- PowerShell late-bound COM to SOLIDWORKS fails on this PC (TYPE_E_ELEMENTNOTFOUND), so the
  scriptable path is the early-bound C# `FastenerCli.exe`, sharing `SwImport.cs`/`Catalog.cs`
  with the add-in.
- Dany does not use OneDrive: nothing is written to the OneDrive-redirected Desktop; generated
  files go to `FASTENERS/custom/`. Saved as a memory rule.
- Unidentified requests "DIN 7401" and "DIN 913.3" were implemented as DIN 7991 and DIN 915
  (likely intent, told Dany); "DIN 4398" was left out pending clarification.
- DIN 7984 key sizes, DIN 316 wing shape, DIN 546 proportions, DIN 582 forged shape, circlip
  lugs/openings and the E-clip shape are catalogue-typical / representative, flagged in the
  catalog notes.
