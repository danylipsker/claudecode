## Summary

Dany asked for "a very comprehensive app, full of riddles and puzzles of any kind possible" —
matches, coins, cards, glasses, paper, compass and ruler, weights and the rest — playable on the
screen with real hand tools (notes, zoom, colouring, grouping, see-through, stacking order,
cutting, knotting, 2D and 3D, folding), with hints, humour, links between related puzzles, sources
from books and the web in the Martin Gardner spirit, the dark Sokoban/Sliding Blocks look, and at
least 2,000 puzzles. Later: "you can add endless riddles, no limitations". The result is
`PUZZLES/`, **The Puzzle Cabinet**: 9,404 stored puzzles in 148 drawers on 18 shelves, 118
Endless drawers that make new solver-checked puzzles at five levels, every stored puzzle verified
by its engine in node and played through to "solved" in the browser. It is linked at the top of
"Puzzles and games" on the root page; this commit publishes it on GitHub Pages.

## Decisions

- **Plain JS, no build step, one engine file per kind of puzzle**, registered on a global
  `Cabinet`; engines must keep `verify()` node-safe so every puzzle is checked outside the browser.
  This is what let 40+ writers work in parallel without touching each other's files.
- **Writers never edit core files**; they report "core wishes" and the lead implements them in
  js/*. Many hooks in the workbench (hover, right-press, long-press, `singleDrag`, `keepView`,
  `modesFirst`, tool previews, `stateVersion`) exist because a writer asked.
- **Endless puzzles are generated and verified on demand** (`engine.generate(rng, level)`,
  25 seeds within 6 s, each `verify()`d), not stored — "no limitations" without a huge download.
- **Puzzles are retold in our own words and credited** (Rhind papyrus to Dudeney and Loyd); no
  copying of book text.
- **Saved games are capped at 200.** The site's localStorage is shared with the other apps (10 MB);
  a long self-test once stored 3,300 games, storage filled and the app froze. Oldest first is
  dropped; an unfinished game older than 200 others is the acceptable loss.
- **Browser self-tests run in chunks of at most ~500 puzzles per fresh tab.** One 1,230-row run
  froze the tab after ~600 puzzles; the same rows in chunks all passed with flat memory
  (~40 MB). `cipher-journey` needs `wait: 60000` (slow animation, not a bug).
- Rejected: running 16 Opus writers at once (hit the 5-hour limit; resumed later with
  SendMessage) — run fewer in parallel.

## Open threads

- Dany set no upper limit ("keep going"): more drawers can be added any time by following
  PUZZLES/AUTHORING.md, then `node tools/validate.js` and `node tools/catalog.js`.
- Some Endless generators return nothing at the hardest level for some seeds (the drawer retries;
  no invalid puzzle is ever shown) — worth tuning per family.
- `knights-tour` `tour-numbered-10` verification takes ~1.7 s in node (the slowest check).
- The paint-drag fix was checked with synthesized mouse drags only; a real touch drag on a phone
  has not been tried.
- After any browser self-test, clear `pc:*` keys (except `pc:settings`) so Dany starts clean.
