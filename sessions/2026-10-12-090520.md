# Session — 2026-10-12 (formula variable tooltips)

**Branch:** main · **Commit:** bd7d2d4

## Summary
Dany asked for a tooltip on every variable of every formula in the Hyper apps, and a default
value for each variable where possible. Both are done through the shared formula card in
HYPER-CORE, so all 17 apps get it at once: pointing at a variable's symbol or name in the list,
or at its symbol inside the written formula, now explains the variable. Default values turned
out to be already complete across the 8,673 formulas.

## What changed
- The formula card builds a tooltip per variable from what the formula knows: role (given /
  the unknown / constant / fixed), quantity and unit with the other units offered, starting
  value, the value now when it differs, range, signed / whole-number flags, and an author's
  optional `hint` sentence (HYPER-CORE/js/ui/calc.js).
- Triggers: mouse hover on the symbol button, the name, or a `[data-k]` symbol in the
  formula display; keyboard focus on the symbol or the name (the name is now focusable);
  a tap on the name on touch screens toggles it. Clicking a symbol to make it the unknown
  refreshes the tooltip. Escape, scroll, resize, hash change and clicking elsewhere hide it.
- The native `title` tooltips on the symbol button and the formula display were removed so the
  two do not stack; the symbol keeps an aria-label "Solve for …".
- `.vtip` styling in both themes, `cursor: help` on names and formula symbols (hyper.css).
- AUTHORING.md documents the per-variable `hint` field (formula.js already carried it through,
  unused until now).

## Decisions
- Generated tooltips rather than authored text: 32,656 variables exist and none had a hint,
  so a hand-written sentence each was out of scope for a session. The `hint` field is the hook
  for writers to add one where the generated facts are not enough.
- One tooltip element for the whole page (like the link-preview popover), positioned fixed,
  pointer-events none, with a 200 ms hover delay and none on focus / tap.
- No content edits for default values: a census script showed every given variable already has
  a `value`; the 21 without one are each formula's computed unknown. The validator already
  warns when a given variable lacks a value, so this cannot regress silently.
- Constants show their standard value to seven figures in the tooltip (an ordinary value shows
  four), so 9.80665 does not read as 9.807.

## Open threads
- No variable has an authored `hint` yet; a writers' pass per app could add one where the
  meaning is not obvious from the name (e.g. sign conventions, what is measured from where).
- Verification lesson: the built-in browser pane delivered no mouse events to the page while
  the app window was hidden (an event log on the page stayed empty) and screenshots timed out;
  the behaviour was verified by dispatching the events from script and reading the tooltip
  text, plus one real hover screenshot taken while the pane was drawing.
