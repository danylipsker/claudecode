## Summary

Dany wanted to see every Sokoban level while playing, and to play them anywhere, not only on this
PC. The Levels button used to show only the 16 hardcoded levels. The 1.5 million Boxoban levels
could only be played by opening their files one at a time with **Open**, and the 171 MB dataset is
gitignored, so it lives only on this machine. The game now has a level library with every
collection. 3,503 levels are built into the page, and the two large Boxoban collections download
1,000 levels at a time and then stay on the device. The game works offline and installs on a phone.
It is pushed and live on GitHub Pages at https://danylipsker.github.io/claudecode/sokoban/sokoban.html.

## What changed

- The picker was replaced by a **Level library** (key `L`). Chips switch collection, a slider and
  ◀ ▶ step through sets of 1,000, **Go** jumps to a level number, **Random** picks a level not yet
  solved, and every level shows as a lazily drawn thumbnail. The "Classic Levels" button and the
  separate pack browser are gone, because files opened with **Open** now appear as one more chip
  (sokoban/sokoban.html)
- Built-in collections: Classic 16, Microban 155 (niveles.txt, with its quoted level titles such as
  "The Dungeon" shown in the subtitle) and Boxoban Hard 3,332 (sokoban/sokoban.html)
- Boxoban Medium (500,000) and Unfiltered (1,001,000) are fetched from
  raw.githubusercontent.com/google-deepmind/boxoban-levels, one dataset file per set, with jsDelivr
  as a fallback and a 20 s timeout. On localhost the local `boxoban-levels-master/` is tried first.
  Each set is stored packed in IndexedDB (`sokoban-levels` / `sets`, keyed by dataset path, e.g.
  `medium/train/123`) (sokoban/sokoban.html)
- Packed Boxoban format: the 64 inner cells of the walled 10x10 board, three cells to a byte in
  base 5 over `" #$.@"`, 22 bytes a level. The same code packs the embedded Hard set and the
  IndexedDB copies (sokoban/sokoban.html, sokoban/tools/embed-levels.js)
- `tools/embed-levels.js` writes Microban and Hard into two `<script type="text/plain">` blocks and
  checks that unpacking what it packed gives back the same levels (sokoban/tools/embed-levels.js)
- The address names the level (`#hard/1234`) and reacts to `hashchange`. The resume point is
  remembered per collection (`progress.at[id]`) and the last collection in `progress.last`. At
  startup the game opens the level in the address, else the resume point, and falls back quietly
  to Classic if that set cannot be loaded offline (sokoban/sokoban.html)
- Offline and phone install: `sw.js` (network first, cache `sokoban-v1`, only clears caches with
  its own `sokoban-` prefix, `?nosw` skips it), `pwa.json`, `icon.svg`, PNG icons at 180/192/512
  drawn by `tools/make-icons.js` with no dependencies (sokoban/sw.js, sokoban/pwa.json,
  sokoban/tools/make-icons.js)
- The minimum cell size went from 20 px to 8 px, so the widest level (Microban 155, 30 columns)
  fits a 375 px phone (sokoban/sokoban.html)
- Bug fix: Enter after a win skipped a level (1 → 3), because the keydown handler and the focused
  Next Level button both advanced. The keydown now calls preventDefault, and the button acts only
  while `state.won` (sokoban/sokoban.html)
- Reset Progress now needs two presses and clears only the collection on show; before, it wiped
  everything (sokoban/sokoban.html)
- The apps page description was updated, and a sokoban README was added (index.html,
  sokoban/README.md)

## Decisions

- **Embed only what is small, fetch the rest.** Microban and Hard add about 115 KB to the page
  (75 KB gzipped) and then work from `file://`, offline and inside the service-worker cache with
  nothing extra to fetch. Medium and Unfiltered are about 1.5 million levels, around 33 MB even
  packed, so they could never ship in the page.
- **Fetch from DeepMind's public repository instead of vendoring the dataset.** 171 MB of text
  would bloat the repo, and GitHub Pages would serve it no better. Both raw.githubusercontent.com
  and jsDelivr send `Access-Control-Allow-Origin: *`, verified with curl and in the browser. This
  works even from an opaque origin (the page opened from disk).
- **Sets of 1,000 = one dataset file.** This is the natural unit for downloading, caching and the
  slider. The collection index is global (Medium 450,001 is `medium/valid/000` level 0), so
  progress keys stay `pk:<collection>:<global index>`.
- **Progress keys kept compatible.** Classic stays `lv<i>`, so old bests survive. The old
  `pk:niveles.txt:<i>` keys are copied to `pk:microban:<i>` at load. The old `pk:000.txt:<i>` keys
  were **not** migrated, because the file name does not say which dataset folder it came from
  (hard/000, medium/train/000, …). They still apply if that file is reopened with Open.
- **GitHub Pages is the "anywhere".** The repo is public and Pages was already serving `main` at
  the root, so pushing was the whole deployment. Dany approved the push explicitly. No claude.ai
  artifact was made: the page needs a service worker and cross-origin fetches, which Pages handles
  naturally.
- **Service-worker caches are per origin, not per app.** Every app on danylipsker.github.io shares
  one cache store, so the Sokoban worker deletes only caches that start with `sokoban-`.
- **`HYPER-DRIVING/DRIVING-SIGNS/` was left out of every commit.** It is untracked work (439 traced
  sign SVGs, index.csv, _tools) that another session was editing at the time of this close-out
  (`signtrace.py` was modified at 09:27). It is not part of this session.

## Open threads

- **Hyper Driving's service worker deletes every other app's cache.** In `HYPER-DRIVING/sw.js`,
  `activate` deletes every cache whose name `!== CACHE`. Caches are shared across the origin, so
  when Hyper Driving ships a new worker it also wipes `sokoban-v1` (and any future app's cache).
  Sokoban re-caches itself on its next online visit, so the harm is limited: it is offline only
  after a Hyper Driving update and before the next online visit to Sokoban. The fix is to filter
  on a `hyper-driving-` prefix, as sokoban/sw.js does. Not changed here because another session was
  working in HYPER-DRIVING.
- **Not tried on a real phone.** The 375 px layout was checked in the browser pane. The service
  worker, the offline reload with the server stopped, and the live Pages URL were all checked, but
  Add to Home Screen on actual iOS or Android hardware was not.
- **Startup fallback not exercised end to end.** The path where the last-played Medium or
  Unfiltered set is not stored and there is no connection was only reviewed as code. The failure
  paths inside the library (error message, Try Again, stored sets still opening) were exercised by
  blocking `fetch`.
- **Boxoban levels have no par.** The HUD shows "—" for them. A solver to grade them, or a
  difficulty sort, is still an idea (it was already noted in the 2026-08-25 session).
- The library panel has a fixed height (`min(88vh, 780px)`), so small collections leave blank
  space. This was chosen so the panel does not jump when switching collections; revisit if it
  looks empty.
- `sokoban/_preview_sokoban.html` is still a stale, gitignored draft. It can be deleted.
