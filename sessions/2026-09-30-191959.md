## What changed

- The generating roll sweep now reaches the tip and the form circle, using the closed-form span instead of a fixed guess (involute.py, internal.py, 1f8be94).
- A helical gear's cutter fillet is now an ellipse: the normal-section circle stretched by 1/cos β (involute.py, 868e6b3). The strain-wave ring check's contact floor was corrected to follow (a02a765, 6f22f4b).
- A helical rack's root fillet is now an ellipse too (rack.py, 822d751).
- The spiral bevel's flat virtual gear is now cut by the blade's normal profile, stretched (spiral_bevel.py, 4db9c86).
- The cylindrical worm's thread, root fillet included, is now a true screw, built by twist-extruding its transverse section instead of lofting (worm.py, 85e3d0c).
- The worm's wheel is now the worm's axial rack in the wheel's mid-plane: its transverse module and pressure angle are the worm's axial ones. The preview also turns the wheel into mesh, and the card's wheel hint was fixed (worm.py, server.py, GearViewModel.cs, 624af73).
- The globoid worm's hourglass root is now revolved as an exact torus arc instead of a 48-segment polyline (4.9 µm off at m=4). The thread itself was measured and was already exact (globoid_worm.py, d26971e).
- The globoid worm has a root fillet (new parameter `root_fillet_coeff`, default 0.2). Its stations are lofted as true line and arc edges, and the fillet is limited so it stays clear of the wheel. The server reports the radius actually used (`worm_root_fillet_mm`), and the preview and DXF are closed along the root circle (globoid_worm.py, throated_wheel.py, server.py, build_gear.py, GearViewModel.cs, 8db99cd).
- The DXF exporters pass `close=True` to ezdxf's `add_lwpolyline` instead of the deprecated `"closed"` attribute, at all 20 call sites; the written closed flag is unchanged (build_gear.py, strain_wave.py, 87f3799).
- Closed DXF outlines no longer repeat their first vertex. Every closed polyline used to append it *and* set the closed flag, so the file carried a zero-length segment before the real closing one (24 of the 26 gear types). A new `add_closed_lwpolyline` drops a repeated end vertex; every exporter uses it. The bevel heel-tooth profile, which was an open polyline closed by the repeat (twice over, after shapely's own ring repeat), is now closed like the others. Read back, every polyline is the same vertices in the same order minus the repeat, symmetric difference 0.0 mm². New `tests/test_dxf_export.py` guards it and fails 9 of 10 on the old code (build_gear.py, strain_wave.py, 1142e85).

## Decisions
- **The globoid wheel is cut with a sharp-root hob, not a filleted one.** A filleted hob changed the wheel (+35.7 mm³ at ρ* 0.2). At ρ* 0.38 the production generation refused outright: the space spanned 582% of the pitch at the rim. So the fillet is limited to stay outside the wheel's tip circle, where it can't touch the wheel. That makes the sharp hob equivalent, and the wheel is unchanged (32 309.5846 mm³ at every ρ*).
- **The globoid fillet has two limits:** a sliver of root land left at the tooth centreline (the full-round limit), and the wheel's tip circle plus 1 µm. At ρ* 0.38 (the app's shared default) it is held to 0.3618. The limit is silent, which matches the other gear types; the radius used is shown on the card.
- **The fillet stops 1 µm short of the root circle.** Where it touched the core torus exactly, OpenCASCADE's fuse returned nothing.
- **Loft through true lines and arcs, not polylines.** ThruSections with compatibility checking off, as the spiral bevel does. Polyline fillets made a 4-start globoid worm take 18.6–28 s to build (mostly the fuse); with true edges it takes 2.0 s, exact to 0.02 µm.
- **The cylindrical worm thread is twist-extruded, not lofted.** The ruled loft was 37 µm off between stations.
- **The worm wheel's `GearParams` gets normal-section values** (m_x cos γ, atan(tan α_x cos γ), coefficients / cos γ), so its transverse values are exactly the worm's axial ones.
- **The DXF closing vertex went in its own commit**, after the deprecation rename: the rename changes nothing in the file, the vertex drop does (one vertex fewer per outline), so they are separable in history. `fibonacci_gear.py`'s three polyline calls were already right (they strip shapely's repeat) and were left alone.
- **Git workflow:** work stays in the worktree branch, and each commit is pushed only when the user says "push it", as a fast-forward `git push origin HEAD:main`. Don't push the branch ref: the user had the remote branch deleted. The main checkout has other sessions' uncommitted work, so never reset, stash or check out over it.
