## What changed

  It builds the HID service itself with the core's own `BLEHIDDevice` class: a 45-byte report map written out byte by
  byte with a comment per item, 8-byte press and release reports, bonding through `BLESecurity`, the keyboard
  appearance code. Letters, digits and the space are typed from a four-line key-code rule instead of a 128-entry table.
  The page's `about`, `needs`, `libs`, notes, body paragraph and MicroPython note were rewritten to match.
- **Arduino_GFX notes corrected on five pages** (`content/graphic-displays.js`): "1.6.4 did not build with core
  3.3.7; 1.6.9 does", instead of pointing the reader at the old core.
- **`compile-esp32.js` gained `--redo`** to rebuild chosen programs that built before (needed after a library is
  updated), and the report's section for programs built with another core version now explains both reasons for it.
- **`COMPILED.md` regenerated**: 614 built (1 only with Huge APP, 7 as one part of a sketch, 2 Matter programs with
  core 3.3.12), 0 need a library, 0 need a newer core, 6 other board / own file, 0 failed.
- **`API-CRIB.md` Appendix C**: the ESP32-BLE-Keyboard finding, the ESP32-A2DP 1.8.11 calls that build, the Arduino_GFX

## Decisions
- **Core 3.3.12 went into `C:\arduinoData`, not the IDE's own data folder.** It replaced the 3.3.3 that was there,
  which was only needed for Arduino_GFX 1.6.4; updating that library to 1.6.9 (it builds with 3.3.7) made 3.3.3
  redundant, so I checked that first and then upgraded. The Arduino IDE still runs 3.3.7, untouched.
- **The two GitHub-only libraries were installed by `git clone` at their release tags** into `C:\arduino\libraries`
  (ESP32-A2DP v1.8.11, ESP32-BLE-Keyboard 0.3.2-beta). arduino-cli's own `--git-url` route needs a setting literally
  named "enable unsafe install", which the session's permission check refused; a shallow clone gives the same files.
- **The keyboard program was rewritten rather than the library patched or a fork recommended.** T-vK's library,
  tag and master alike (last commit March 2024), passes `std::string` where the core's BLE library has taken
  `String` since 3.0, so a reader installing it as published would meet the same two errors; and the forks could
  not be verified here. The core's `BLEHIDDevice` is what that library wraps anyway, and writing it out shows the
  report map and the reports the page teaches. The block program and the MicroPython note did not change.
- **The Matter programs were built in a second work folder and merged by hand** into the main `results.json`,
  because the main rebuild was running at the same time and two instances of the tool would have overwritten each
  other's results.

## Open threads
- **Nothing was run on hardware.** The rewritten keyboard program compiles and follows the HID specification, but
  pairing with a real Windows, Android or iOS host is the test that matters; the A2DP and Matter programs are in the
  same position.
- **The six unbuilt programs stay unbuilt by design**: four are for the ESP8266 or an Arduino using an ESP as its
  radio, two include the reader's own trained-model header.
- **To rebuild**: `node HYPER-CORE/tools/compile-esp32.js --work <dir> --sketchbook C:/arduino --libraries
  C:/arduino-adafruit/libraries --jobs 6 --report`; add `--data C:/arduinoData --only matter-commissioning,matter-on-esp`
  for the two Matter programs (then merge their `results.json` entries). The work folder of these sessions was a
  scratch folder; a fresh run rebuilds everything, about five hours.

  himself if the cloud move is still wanted.
