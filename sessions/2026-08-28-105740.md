## Decisions

- **A round tool enforces W = D = Ø (its bounding square), pushed into the same hidden
  W/D textboxes.** That one rule means every existing consumer of the W/D/T/L box — the
  cutting simulation's front-edge math, placement, the fade/ghost logic — works unchanged;
  only the two renderers became shape-aware. Rejected teaching the simulation about
  circles as out of scope (see Open threads). L/T keep their exact meaning for round
  tools, so positioning works identically.
- **W/D lock (gray out) while Round is checked and mirror Ø; Ø/H gray out while
  rectangular** — makes it obvious which four numbers drive the geometry at any moment.
- **Height applies to round tools only**; rectangular blades keep the fixed presentational
  60 mm fin height in 3D, as before.
- **Spinners are WPF RepeatButtons** (Delay 300 / Interval 45) rather than a custom
  control — press-and-hold gives the requested "dynamic" feel with no new dependencies.
- **Live apply goes through MainWindow's own `SetTool{i}Params_Click`** (reflection, the
  dialog's existing pattern) so each spinner step follows the exact same parse-and-redraw
  path as the Set button — one behavior, two triggers.
- Bash heredocs mangled the C# driver source again (same harness quirk the 2026-08-19
  session hit) — driver files go through the Write tool, compiled with the VS Roslyn csc
  against the built exe, run from bin/Debug for assembly resolution.
- The verification driver backs up and restores the user's real `tool_parameters.csv`
  around the CSV round-trip test.
